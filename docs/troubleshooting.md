# 故障排查

## 启动与端口

### 5173 或 3000 被占用

`npm run demo` 会为前端选择可用端口，并把精确 origin 传给后端 CORS。请使用终端打印的地址，不要固定假设 5173。

Electron 后端默认从 3000 开始探测回环端口。若应用停留在恢复页：

1. 查看 `logs/backend.log`；
2. 确认没有旧应用进程占用端口；
3. 检查 `/api/health`；
4. 确认安全软件没有阻止本机回环连接。

### 页面空白

检查客户端生产构建是否存在、CSP 是否报错、静态资源是否返回 200。桌面包使用 runtime-only vue-i18n，不能重新引入需要 `unsafe-eval` 的编译器构建。

## Demo Mode

### Demo 仍提示缺少 Key

确认使用 `npm run demo`，并检查 `DEMO_MODE=1` 是否传入 server。Demo 的脚本、图片和配音应该在网络适配器前短路。

### 担心测试调用付费模型

执行 `npm run test:smoke`。脚本会清空常见 Key，并使用临时数据目录。不要在测试命令外层重新注入 `.env`。

## Provider

### 401/403

- 重新保存凭证；
- 检查 baseUrl 是否属于该 Key；
- 某些兼容中转要求不同模型名；
- Kling 等双密钥协议需要同时配置 Access Key 和 Secret Key。

鉴权失败默认不重试，避免快速消耗配额或触发封禁。

### 429 或 5xx

任务会记录尝试和退避状态。等待自动重试或选择降级 Provider。批任务部分成功时，只重试失败镜头。

### 返回格式异常

检查 Provider 是否真的兼容所选协议和模型。不要在业务层直接接受未知 JSON；应在适配器中转换，并由契约层 validate。

## 资产与时间线

### 项目显示缺图/缺音频

打开资产健康检查，确认数据库引用对应文件是否存在。恢复数据库备份时还需要恢复同一时间点的媒体目录。

### 修改脚本后预览还是旧内容

脚本或分镜变化会让下游检查点过期。重新执行发生变化的阶段，并确认时间线已刷新，再导出。

### 删除素材后想恢复

默认删除进入回收站。按项目和素材类型查看详情并恢复指定项；永久删除不可恢复，应有明确确认。

## FFmpeg 与导出

### FFmpeg 不可执行

先运行：

```bash
node scripts/ffmpeg-smoke.mjs
```

桌面包内的 `ffmpeg-static` 必须位于 ASAR 解包目录。系统下载的文件若缺少执行权限，需要重新安装依赖或修复权限，不要把本机绝对路径写进仓库配置。

### 导出失败但预览正常

重点检查输出目录写权限、磁盘空间、字幕字体和路径、媒体文件完整性，以及 FFmpeg stderr 中第一个实际错误。修复后只重试 `export`，不需要重新生成脚本和图片。

### 导出文件存在但打不开

不要只检查文件大小。运行 FFmpeg/ffprobe 检查容器与视频流。失败临时文件应清理，避免成片库把它当作成功结果。

## 任务恢复

### 重启后任务没有自动继续

检查任务详情：状态是否属于可恢复集合、`meta.recovery.kind` 是否存在、当前版本是否注册对应 runner、恢复次数是否达到上限，以及数据库/媒体目录是否可写。

`RECOVERY_RUNNER_MISSING` 表示任务数据还在，但当前版本不知道如何继续，需要回到项目手动修复或安装包含该 runner 的版本。

### 恢复反复失败

达到上限后系统会停止自动循环。根据任务错误和 request id 定位阶段，修复输入、目录或 Provider 后手动重试。

## 凭证与设置

### 设置页只显示掩码

这是正常行为。前端不会读取完整 Key。留空保存不会覆盖旧 Key；只有显式清除才删除凭证。

### 迁移旧版本后 Key 消失

检查系统 Keychain/Credential Manager 和后端日志中的迁移摘要。日志只应显示迁移了几组凭证，不能显示凭证值。

## 桌面打包

### macOS 提示 resource fork/Finder information

同步盘或 Documents 目录可能给 `.app` 附加 Finder 元数据。`npm run pack` 默认把 ad-hoc 预检包输出到系统临时目录，并在签名前使用 clean-copy hook 清理扩展属性。

### `codesign` 通过但 `spctl` 拒绝

ad-hoc 包出现该结果是预期的：它只能验证结构完整性。公开发布需要 Developer ID Application 签名、公证和 staple。

### Windows SmartScreen 警告

unsigned 或自签名包不适合公开分发。使用受信任代码签名证书、时间戳服务，并在干净机器验证签名链。

## 提交问题时提供什么

请提供版本、操作系统、复现步骤、任务 id、请求 id、失败阶段、是否 Demo Mode，以及经过脱敏的日志片段。不要上传 API Key、Authorization、完整用户路径、私人素材或数据库。
