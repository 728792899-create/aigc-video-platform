# AIGC 视频工作台 — 软件加密与防破解历史方案

> 本文保留早期论文与 Windows 验证记录，仅供设计追溯。当前 Electron/Node 版本、文件数量、命令、签名与发布状态以根目录 `package.json`、`README.md`、`docs/desktop-release.md` 和 `docs/release-checklist.md` 为准。ASAR 是归档而不是加密，字节码和混淆只能提高逆向成本，不能替代服务端安全边界。

> 项目：AIGC 辅助的短视频创意生成与制作平台（桌面版）
> 版本：v1.3.0 ｜ 编写：王从天降
> 目标：保护软件底层研发数据（核心 Prompt 工程、业务逻辑、AI 密钥），抬高第三方逆向破解成本。

## 0. 设计前提（必须先对齐）

凡是在用户机器上运行的代码，**理论上都可被逆向**——这是物理事实。Electron 应用尤甚，本质是「Node.js 源码 + Chromium」。

因此本方案目标**不是「绝对不可破解」**，而是：

> 把破解成本抬高到远超破解收益，让普通人无从下手、让懂行者觉得不值得。

真正值钱、必须治本的资产（AI 密钥、最核心 Prompt）唯一彻底的方案是**服务端化**——不下发到用户机器。客户端侧的一切手段（混淆、字节码、加密）都只是「抬高成本」，不是「绝对安全」。

---

## 1. 当前暴露面盘点（基于真实代码审计）

打包配置 `package.json` 中存在最致命的一行：

```json
"asar": false
```

安装后 `resources/server/` 下**所有后端源码、node_modules、Prompt 工程均为明文**，任何人进安装目录用记事本即可阅读。

| 资产 | 当前状态 | 风险 |
|------|---------|------|
| 后端业务逻辑（Express 全套） | 明文 .js | 🔴 极高 |
| **Prompt 工程**（6 内置技能 / DETAIL_LEVELS / buildSystemPrompt） | 明文，核心 IP | 🔴 极高 |
| AI 服务密钥（settings.json / env） | 明文存储 | 🔴 极高 |
| 前端代码 | Vite 已 minify，可还原 | 🟡 中 |
| 数据库结构 / 业务数据 | SQLite 明文 | 🟡 中 |
| 安装包整体 | 无签名、无完整性校验，可被篡改植入后门 | 🟡 中 |

**结论：当前等于把全部研发数据敞开放在用户硬盘上。这是本方案要解决的核心问题。**

## 2. 分层防护架构（5 层，由浅入深）

### Layer 0 — 打包加固（地基，必做）
- `asar: false` → **`asar: true`**：源码打进 asar 归档，普通用户无法直接浏览。
- 开启 **asarIntegrity**（electron-builder 25+ 内置）：启动校验 asar 哈希，被篡改即拒绝运行。
- ⚠️ 副作用：当前 asar:false 是为让 `ffmpeg-static` 与 `fork` 子进程可执行。改 true 后须用 `asarUnpack` 把 `server`、`ffmpeg-static` 解包到 `app.asar.unpacked/`，否则后端起不来。

### Layer 1 — 前端混淆
- 用 `javascript-obfuscator` 对 `client/dist` 做混淆：控制流扁平化、字符串数组加密、死代码注入、selfDefending。
- DevTools 中看到的全是乱码，minify 产物彻底不可读。

### Layer 2 — 后端 V8 字节码编译（核心防护）
- 用 **`bytenode`** 把后端 `.js` 编译成 `.jsc`（V8 字节码二进制）。
- Node 侧性价比最高：源码变二进制，反编译回可读 JS 极困难。
- 配合 Layer 1，做到「先混淆再编字节码」双层。

### Layer 3 — 密钥与最核心逻辑保护（重点，治本）
密钥**绝不能跟着软件走**。三选一（按强度）：
1. **服务端代理（最强，推荐）**：AI 密钥放自己的服务器，客户端只调中转接口，密钥永不下发。需维护服务器 + 调用鉴权。
2. **机器绑定加密**：密钥 AES 加密存储，解密 key 由「机器指纹（主板/CPU/MAC）+ 内置盐」运行时派生，拷到别机无法解密。
3. **Native 插件（最硬）**：许可证校验、密钥解密写进 C++ N-API 编译成 `.node` 二进制，逆向门槛远高于 JS。

### Layer 4 — 授权 + 防篡改 + 签名
- **授权激活**：机器指纹绑定 + RSA/ECDSA 签名 License 令牌，可选在线激活，防一份到处拷。
- **反调试**：生产环境检测 DevTools / debugger，触发即降级或退出。
- **代码签名**：给 `.exe` 数字签名，防篡改 + 消除 SmartScreen 警告（需购买代码签名证书）。

## 3. 推荐落地路线（分阶段，对毕设务实）

不建议一上来全做——L3/L4 全套是企业级 DRM，对毕设属过度工程且易引入运行时 bug。

| 阶段 | 内容 | 工作量 | 防护提升 | 风险 |
|------|------|--------|---------|------|
| **P0（强烈建议，立即做）** | asar:true + integrity + 前端混淆 + 密钥从明文挪走（至少 AES+机器绑定） | 半天 | 🔴→🟢 挡住 99% 普通人 | 低 |
| **P1（建议）** | 后端 bytenode 字节码编译 + 反调试 | 1~2 天 | 挡住大部分业余逆向 | 中（需充分测试） |
| **P2（可选/论文未来工作）** | License 授权系统 + Native 插件 + 代码签名 | 3~5 天 | 商业级 | 高 |

**对答辩**：P0 + P1 已是漂亮的「软件知识产权保护」章节，可现场演示「安装目录全是乱码/二进制、看不到任何源码和密钥」。P2 写进论文「未来工作」体现技术视野。

## 4. 已知副作用与限制（诚实告知）

- **bytenode 非银弹**：字节码仍可被动态 dump，且绑定 Node 版本，升级 Electron 需重编。
- **混淆有性能开销**：控制流扁平化会拖慢代码，热点路径应排除。
- **asar:true 改动有破坏性**：`fork` + `ffmpeg-static` 必须正确 unpack，否则后端起不来——落地时端到端验证。
- **无法防内存抓取**：没有任何客户端方案能防住运行时内存 dump，所以密钥/核心 Prompt 最好走服务端，这是唯一治本方案。

以下为旧版本 1.4.0 的历史验证记录。当前产品名称、构建产物和发布验收以根目录 README 与 `docs/release-checklist.md` 为准；旧版产物约 110 MB，该记录不代表当前签名或发布状态。

| 层 | 措施 | 原状态 | 修正后 | 装体验证证据 |
|----|------|--------|--------|------|
| L1 前端混淆 | javascript-obfuscator | client/dist 业务块 minify 但可读 | 19 业务块控制流扁平化+字符串base64+selfDefending；element-plus/vue-core 开源框架跳过 | 装体 `Script-*.js` 全 `_0x` 乱码，grep `expand-dialog/应用当前配音` 0 命中 |

| L2 后端字节码 | bytenode 1.5.7 | resources/server 全明文 .js，Prompt 工程裸奔 | 业务 .js 按当前源码数量编译为 .jsc(V8字节码)，仅留 app.js bootstrap | 安装体业务源码不再明文分发；字节码后端实启动 health/skills/presets/version 全 200 |

**新增构建产物（不污染开发目录）：**
- `scripts/obfuscate.js` — 前端混淆（post-build，跳过开源框架）
- `scripts/compile-backend.js` — 后端字节码编译（复制 server→dist-server-jsc，编译.jsc，入口生成 bootstrap）
- `scripts/secure-build.sh` — 一键安全打包流水线（构建→混淆→字节码→electron-builder）
- `dist-server-jsc/` — 后端字节码中间产物（打包源，extraResources 已指向它）

**关键技术约束（踩坑记录）：**
- bytenode 字节码**版本绑定**：必须用目标 Electron 内置 Node 编译（`ELECTRON_RUN_AS_NODE=1 ./node_modules/.bin/electron`），不能混用系统 Node，否则运行崩溃。
- 无扩展名 `require('./x')` 在 `require('bytenode')` 注册后能自动解析到 `x.jsc`，**无需改写 45 文件的 require**。
- 后端走 `extraResources`（fork 子进程需真实磁盘路径，不能在 asar 内），所以 **asar 保护不到后端**——后端 IP 只能靠 bytenode。
- asar:true 后 `require('ffmpeg-static')` 返回 app.asar 内路径，须 main.js 里 `.replace('app.asar','app.asar.unpacked')` 重定向。
- 本机 NODE_ENV=production + npm omit=dev：装 devDep 必须 `unset NODE_ENV && npm i <pkg> --include=dev --production=false`。

**一键安全打包命令：**
```bash
cd /path/to/aigc-video-platform && unset PORT && bash scripts/secure-build.sh
# 仅 win-unpacked 不出安装包：bash scripts/secure-build.sh --dir
```

## 7. P2 代码签名（✅ 自签名链路已打通，2026-05-31）

代码签名分两类，先讲清楚：
- **商业证书**（CA 颁发，需付费购买）：唯一能消除安装时 Windows SmartScreen 警告的方式，证书链被系统默认信任。
- **自签名证书**（本地免费生成）：能证明「文件未被篡改」+ 附带可验证发布者身份 + 时间戳，但默认不被系统信任，**不能消除 SmartScreen**（除非用户手动导入信任）。

本次在不购买商业证书的前提下，用 PowerShell 原生 cmdlet（无需 Windows SDK signtool）走通了**完整签名工具链**，为论文「代码签名」章节提供可演示内容。

**工具链（`scripts/sign-app.ps1`，3 个 action）：**
| Action | 作用 | 关键 cmdlet |
|--------|------|------|
| gencert | 生成自签名代码签名证书（SHA256/RSA2048/5年）+ 导出 PFX(含私钥)+CER(公钥) | New-SelfSignedCertificate -Type CodeSigningCert / Export-PfxCertificate / Export-Certificate |
| sign | 用 PFX 对 .exe 做 Authenticode 签名 + DigiCert 时间戳 | X509Certificate2 加载 PFX / Set-AuthenticodeSignature -TimestampServer |
| verify | 验签，显示状态/签名者/指纹/时间戳 | Get-AuthenticodeSignature |

**验证闭环（关键演示）：**
1. 签名前 verify → `NotSigned`。
2. 开发自签名证书仅用于本地验证签名链路；正式发布必须使用受信任 CA 颁发的代码签名证书。
3. 把 .cer 导入「受信任的根证书颁发机构」后 verify → **`Valid`**。**证明签名链路完全正确，唯一差别就是证书是否被公共 CA 信任。**
4. 撤销测试信任 → 回到 UnknownError（系统恢复干净，不长期留自签名根）。
5. 签名版 110,124,936 字节 vs 未签名 110,117,676 字节（+7,260 字节证书块），证明签名确实写入 PE 文件。

**已集成进流水线：** `secure-build.sh` 加 [5/5] 签名步骤（条件执行：证书存在 + 生成了安装包才签，--dir 模式跳过，签名失败不阻断构建）。

**关键踩坑：**
- PowerShell 5.1 把无 BOM 的 .ps1 按系统 GBK 码页读取，中文输出会乱码破坏语法解析——**脚本内全用英文输出**。
- PS 5.1 不支持内联 `if` 表达式（`(if(..){..}else{..})` 报错），用 `if/else` 语句块。
- PS 5.1 `Get-PfxCertificate` 无 `-Password` 参数——改用 `New-Object X509Certificate2 -ArgumentList $pfx,$Password,'Exportable,PersistKeySet'` 加载带密码 PFX。
- 本机无 Windows SDK signtool、无 osslsigncode，但 PowerShell 5.1 自带 New-SelfSignedCertificate/Set-AuthenticodeSignature/Get-AuthenticodeSignature/Export-PfxCertificate 全部可用，零额外依赖。

**证书文件（勿提交版本库）：** `build/codesign/aigc-video-studio-dev.pfx`（含私钥）+ `.cer`。密码必须通过 `WINDOWS_PFX_PASSWORD` 或交互参数提供，禁止写入源码、文档和 CI 日志。

**对答辩/论文：** 可现场演示「签名前 NotSigned → 签名后嵌入证书与时间戳 → 导入信任后 Valid」完整链路，论文中说明「已实现签名工具链，商业证书购买后替换 PFX 即可消除 SmartScreen」即可。
